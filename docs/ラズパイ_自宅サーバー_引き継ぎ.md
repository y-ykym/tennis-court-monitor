# 自宅サーバー(Raspberry Pi 5)引き継ぎ — テニスコート予約支援の常時稼働機

別セッションで「Raspberry Pi 5 の購入・セットアップ」を進めるための引き継ぎ。
用途側の設計・実装はリポジトリ `y-ykym/tennis-court-monitor` にあり、詳細は
`docs/フェーズ2_予約支援_引き継ぎ.md`(経緯・決定事項)と `booking/pc/README.md`(現行の起動手順。Windows 前提なので Pi 向けに書き直し予定)を参照。

## 1. 用途(何を動かすか)

- 東京都のテニスコート予約サイトを **自宅回線から** 自動操作する小さなサーバー。LINE の通知カードの「予約」ボタン → Cloudflare Worker(固定 URL)→
  Cloudflare Tunnel → この Pi 上のサーバー → 予約サイトにログイン・枠選択・「予約」まで自動 → 結果を画面と LINE に返す
- **自宅回線であることが本質**。予約サイトは reCAPTCHA v3 で採点し、データセンターの IP(Cloud Run / GitHub Actions)からは
  確定時に v2 の画像問題が毎回出て実用にならなかった(実予約 0/3)。自宅回線(SoftBank Air)からは画像問題なしで成立(Mac で 4/4)
- 処理内容: Docker コンテナ1つ(Node + Playwright + Chromium(headful、仮想ディスプレイ Xvfb)+ x11vnc + noVNC)。
  同時に扱うのは 1 件、1 回の処理は 30〜60 秒、利用は週に数回。メモリのピークは約 1.5GB
- reCAPTCHA v2 が出た場合だけ、noVNC でスマホに画面を映して人間が解く(自宅回線では原則出ない)
- 補助コンテナ 2 つ: `cloudflared`(quick tunnel)と URL 登録スクリプト(Node、2 分ごとに Worker へ現在の URL を登録)

## 2. なぜ Raspberry Pi 5 か(2026-09-05 決定)

- 候補: 古い Windows ノート(NEC NX750/JAW, 2017)の増強 / Pi 5 / N150 ミニ PC / Mac mini
- ノートは 5400rpm HDD で常時ディスク 100%、Windows 11 23H2(サポート終了)、9 年物(バッテリー膨張の懸念)。Windows のまま 24 時間サーバーは不向き
- Pi 6 は 2028 年より前に出ない(2026-05 公式 AMA)→ 待つ意味なし
- 2026 年は DRAM 高騰で全体的に値上げ: Pi 5 8GB ¥36,300 / 4GB ¥22,330(入荷未定)/ N150 ミニ PC 16GB は ¥50,000 超 / Mac mini M4 16GB 約 ¥85,000〜95,000
- **サーバー用途として割り切る**なら Pi 5 が最適: ヘッドレス前提(画面・ログイン不要で自動復帰)、強制再起動する更新が無い、
  待機 5W 前後・月 100 円程度、無音、新品保証。Mac mini はログイン状態で Docker Desktop が動く前提で無人運用の据わりが一段落ちる
- **環境は実証済み**: Apple Silicon Mac の Docker(Linux arm64 コンテナの Chromium)で自宅回線から自動予約が成立(2026-09-05、34 秒)。
  Pi 5 でも同じコンテナイメージがそのまま動く(Google Chrome 本体は ARM Linux に無いため Chromium。成功実績は Chromium)
- 4GB でも足りるが入荷未定のため、いま買えるのは 8GB。4GB が入荷すれば ¥14,000 安い

## 4. 前提となる自宅環境

- 回線: SoftBank Air(モバイル網の家庭用ルーター)。ポート開放不可だが、Cloudflare Tunnel は外向き接続のみなので問題なし。
  cloudflared は `--protocol http2` で張る(QUIC/UDP は家庭用回線で不安定なことがある)
- この回線からの予約サイト操作は reCAPTCHA v3 を通ることを実測済み
- 置き場所: 常時電源・Wi-Fi または有線 LAN が届く場所

## 5. セットアップ計画(実機前提。手順の本体は booking/pc/README.md)

1. Imager で microSD に OS Lite 64-bit(hostname tennis-pi / user yu / Wi-Fi SoftBank Air / TZ Asia/Tokyo / SSH 公開鍵のみ)
2. ケース無しで組み立て → SSH → `pi-init.sh`(更新・EEPROM・Docker・clone・.env 雛形)
3. `pi-check.sh --smart` で SN530 の使用時間を確認
4. `rpi-clone nvme0n1 -f` → `BOOT_ORDER=0xf416` → NVMe 起動(まず Gen2。Gen3 は任意)
5. `.env` 入力 → `docker compose up -d --build` → `pi-check.sh` で疎通確認
6. 実枠で通し(予約→キャンセル)→ GitHub Secrets に BOOKING_BASE_URL → 運用開始 → ケース到着後に組み込み

## 6. 既存の周辺部品(変更不要)

- GitHub Secrets: `BOOKING_SIGNING_SECRET`(登録済み)、`BOOKING_BASE_URL`(Pi が動くまで未登録 = 通知にボタンを出さない)
- GCP プロジェクト `tennis-booking-c46c52c5`: Secret Manager に `booking-signing-secret` / `site-user-a` / `site-pass-a` / `label-a`。
  Cloud Run `tennis-booking` は不使用(0 円。後で削除可)
- コンテナイメージは `booking/Dockerfile`(Playwright 公式イメージ + Xvfb + x11vnc。arm64 でビルド可。Chrome は amd64 のみなので Pi では Chromium)

## 7. 注意点(決着済みの項目は除いた)

- NVMe 起動は EEPROM の起動順設定が必要(microSD → rpi-clone → 切替の順が安全)。PCIe はまず Gen2、Gen3 は任意
- SN530 はバルク品。SMART で使用時間・書込量を確認し、異常なら店の初期不良対応(180 日)へ
- ケース到着まで基板むき出し。絶縁物の上に置く
- quick tunnel は URL が起動ごとに変わる(Worker が吸収)。固定ホスト名にしたければ Cloudflare にドメインが必要(現状なし)
- 予約サイトのセッションは約 10 分で切れる。noVNC が出たら数分以内に操作
- パスワード類はコード・ドキュメントに書かない(`.env` は gitignore 済み)
