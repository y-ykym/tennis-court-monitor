## 4. 注意点(手順書に書かれていない・変わったこと)

- **署名鍵 `BOOKING_SIGNING_SECRET` の値**: `.env` に必要だが、生成時に GCP Secret Manager と GitHub Secrets に入れただけで、**手元に値の記録がない**。
  GitHub Secrets と Worker Secrets は読み戻せない。GCP プロジェクトは 2026-09-07 に削除済み。取り方は 2 つ:
  1. **作り直す(推奨・簡単)**: `openssl rand -base64 32` で新しい値を作り、3 か所に同じ値を入れる。
     GitHub Secrets `BOOKING_SIGNING_SECRET`(`gh secret set BOOKING_SIGNING_SECRET`)、Worker(`cd worker && npx wrangler secret put BOOKING_SIGNING_SECRET`)、Pi の `.env`。
     副作用は「既に配られた一覧カードのキャンセルボタンが無効になる」だけ(押すと無視される。`よやく` を送り直せばよい)
  2. 30 日以内なら `gcloud projects undelete tennis-booking-c46c52c5` で GCP を復元して Secret Manager から読む(復元後にまた削除が必要。面倒なので 1 を推奨)
  `booking/pc/README.md` §6 の表にある「GCP Secret Manager から」という記述はもう使えない
- **パスワードは本人が入力**(`.env` の `SITE_PASS_A` など)。Claude は `nano .env` の開き方までを案内し、値は打たない
- **利用者 B**: `.env` の `SITE_USER_B` 等は任意。Worker 側には B 未登録(「よやく」は A だけ動いている)なので、Pi も A だけで始めてよい
- **テスト予約の後始末**: §7 で取った予約は、LINE で `よやく` → その行の「キャンセル」→「はい」で取り消せる(フェーズ1.6)。テニスは利用日の 4 日前までならペナルティ無し。3 日以内の枠は取らない
- **署名 URL の発行(§7)**: Mac で `booking/src/token.js` の `sign()` を使う。`/book?token=…&person=A` を `https://tennis-reservation-bot.y-ykym.workers.dev` に付けてスマホで開く。有効期限は枠の開始時刻
- **Worker の登録が消える条件**: Pi が止まると 5 分で消え、ボタンは「サーバーに繋がりません。手動で」を案内する。これは正常動作
- **cloudflared は http2**(QUIC は SoftBank Air で不安定なことがあるため)。`docker-compose.yml` にそう書いてある
- ケース(Geekworm P579)はまだ届いていない可能性がある。基板むき出しの間は絶縁物の上で運用する

## 5. よく使うコマンド(Pi 上)

```bash
cd ~/tennis-court-monitor/booking/pc
./pi-check.sh              # 起動ディスク・温度・Docker・/warmup・Worker 登録状況をまとめて表示
./pi-check.sh --smart      # + SSD の SMART
docker compose ps
docker compose logs -f booking
docker compose logs -f registrar
git pull && docker compose up -d --build   # 更新
```
