# 自宅サーバー(Raspberry Pi 5)引き継ぎ — 自己完結版(リポジトリを参照できない相手向け)

この文書だけで「何を・なぜ・どう動かすか」が分かるように、設定ファイルの中身とコマンドも本文に含めている。
秘密情報(パスワード・署名鍵・トークン)は含めない。値は所有者(横山さん)が自分で入力する。

---

## 0. 一言で

東京都のテニスコート予約サイトを **自宅の回線から** 自動操作する小さな常時稼働サーバーを、Raspberry Pi 5 で作る。
中身は Docker のコンテナ 3 つ(予約サーバー本体・Cloudflare Tunnel・URL 登録)で、電源を入れておくだけでよい。

---

## 1. 背景と全体の仕組み

### やりたいこと
- 別の仕組み(GitHub Actions)が予約サイトの空きを 3 分おきに監視し、新しい空きが出ると LINE グループにカードで通知している(稼働中)
- そのカードに「予約」ボタンを付け、押すと **ログイン → 枠の選択 → 「予約」確定** までを自動で行い、結果(予約番号・料金)を画面と LINE に返す

### なぜ自宅回線のサーバーが必要か
- 予約サイトは確定時に Google reCAPTCHA v3 で採点する。**データセンターの IP(Cloud Run、GitHub Actions)からだと毎回 v2 の画像問題が出て自動化できない**(実予約 0/3)
- **自宅回線(SoftBank Air)からは画像問題が出ず、自動で成立する**(Mac からの実測 4/4。2026-09-05 に Linux ARM コンテナで 34 秒で成立)
- Mac は持ち歩くので常時稼働機として使えない → 常時起動の小さな機械を自宅に置く

### 全体の経路
```
LINE 通知カードの「予約」ボタン(署名付き URL)
  → Cloudflare Worker(固定 URL: https://tennis-reservation-bot.y-ykym.workers.dev)  … 玄関。配置済み
  → Cloudflare Tunnel(quick tunnel。URL は起動ごとに変わる)
  → Raspberry Pi 上の予約サーバー(Docker)
  → 予約サイト(自宅 IP で reCAPTCHA v3 を通過)→ 予約成立 → 結果を画面と LINE に
```
- Pi 上の「URL 登録」コンテナが 2 分ごとに、現在のトンネル URL を Worker に登録する(Worker は 5 分で忘れる)。
  Pi が落ちると登録が消え、ボタンを押した人には「予約サーバーに繋がりません。サイトで手動で」と案内される
- reCAPTCHA の画像問題が出た場合だけ、サーバーは画面(noVNC)をスマホに映して人間に解いてもらう。自宅回線では原則出ない

### 処理の重さ
- 同時に 1 件、1 回 30〜60 秒、週に数回。メモリのピークは約 1.5GB(Chromium + 仮想ディスプレイ + Node)。CPU 負荷は軽い
- ストレージの書き込みは少ない(ブラウザプロファイル数十 KB を保存する程度)

## 2. なぜ Raspberry Pi 5 か(2026-09-05 決定)

- 候補: 手元の古い Windows ノート(NEC NX750/JAW, 2017 年, HDD)/ Pi 5 / N150 ミニ PC / Mac mini
- ノートは 5400rpm HDD でディスク使用率 100% 張り付き、Windows 11 23H2(サポート終了)、9 年物でバッテリー膨張の懸念。Windows のまま 24 時間サーバーは不向き
- Raspberry Pi 6 は 2028 年より前には出ない(2026 年 5 月の公式 AMA)→ 待つ意味なし
- 2026 年は DRAM 高騰で全体的に値上げ: Pi 5 8GB ¥36,300 / Pi 5 4GB ¥22,330(入荷未定)/ N150 ミニ PC 16GB は ¥50,000 超 / Mac mini M4 16GB 約 ¥85,000〜95,000
- **サーバー用途と割り切る**なら Pi 5 が最適: 画面もログインも不要で電源投入だけで自動復帰、強制再起動する更新が無い、待機 5W 前後(月 100 円程度)、無音、新品保証
- **環境は実証済み**: Apple Silicon Mac の Docker(Linux arm64 コンテナの Chromium)で自宅回線から自動予約が成立。Pi 5 でも同じコンテナがそのまま動く
  (Google Chrome 本体は ARM Linux に無いので Chromium を使う。成功実績は Chromium)
- 4GB でも足りるが入荷未定のため、いま買えるのは 8GB。4GB が入荷すれば ¥14,000 安い

## 4. 自宅環境の前提

- 回線: SoftBank Air(モバイル網の家庭用ルーター)。**ポート開放はできない**が、Cloudflare Tunnel は Pi から外向きに張るので問題なし
- cloudflared は `--protocol http2` で張る(既定の QUIC/UDP は家庭用回線で不安定なことがある)
- この回線からの予約サイト操作は reCAPTCHA v3 を通ることを実測済み
- 常時電源と、Wi-Fi または有線 LAN が届く置き場所

## 5. Pi にインストールするもの

- OS: **Raspberry Pi OS Lite(64-bit)**(デスクトップ不要)
- Docker Engine + docker compose plugin(公式スクリプト `curl -fsSL https://get.docker.com | sh`)
- git(リポジトリ取得用。`sudo apt install -y git`)
- 予約サーバーのコード: GitHub リポジトリ `y-ykym/tennis-court-monitor` の `booking/` ディレクトリ(public)。
  Pi 用の起動セットは `booking/pc/`(docker-compose.yml、.env.example、README.md)

### コンテナ構成(docker-compose.yml の中身。リポジトリにあるもの)
```yaml
services:
  booking:                      # 予約サーバー本体(Node + Playwright + Chromium + Xvfb + x11vnc + noVNC)
    build: ..                   # booking/Dockerfile(Playwright 公式イメージ + Xvfb + x11vnc。arm64 でビルド可)
    image: tennis-booking:local
    restart: unless-stopped
    env_file: .env
    environment:
      AUTO_CONFIRM: '1'         # 「予約」まで自動で押す。reCAPTCHA v2 が出たときだけ人間に渡す
      PROFILE_LOCAL: '1'        # ブラウザプロファイル(Cookie)を volume に持ち越す
      SCREEN_W: '600'
      SCREEN_H: '1000'
    volumes:
      - profile:/tmp/profile
    ports:
      - '127.0.0.1:8080:8080'   # Pi 自身からの確認用(curl http://localhost:8080/warmup → ok)
    shm_size: 1g

  tunnel:                       # Cloudflare quick tunnel(外からの入口。URL は起動ごとに変わる)
    image: cloudflare/cloudflared:latest
    restart: unless-stopped
    command: tunnel --no-autoupdate --protocol http2 --metrics 0.0.0.0:2000 --url http://booking:8080
    depends_on: [booking]

  registrar:                    # トンネルの現在 URL を 2 分ごとに Worker へ登録
    image: tennis-booking:local
    restart: unless-stopped
    command: node server/register.mjs
    env_file: .env
    environment:
      TUNNEL_METRICS_URL: http://tunnel:2000
    depends_on: [tunnel]

volumes:
  profile:
```

### .env のキー(値は所有者が入力。ファイルは git 管理外)
```
SITE_USER_A=            # 予約サイトの利用者番号(8桁)
SITE_PASS_A=            # 予約サイトのパスワード
LABEL_A=                # 通知や画面に出す呼び名
SITE_USER_B= / SITE_PASS_B= / LABEL_B=   # 2人目(任意)
BOOKING_SIGNING_SECRET= # 署名鍵。GitHub Secrets・Cloudflare Worker と同じ値(GCP Secret Manager の booking-signing-secret にある)
WORKER_URL=https://tennis-reservation-bot.y-ykym.workers.dev
LINE_CHANNEL_ACCESS_TOKEN= / LINE_USER_ID=   # 結果を LINE に push したいとき(任意。GitHub Secrets と同じ値)
VNC_PASSWORD=           # noVNC のパスワード(任意。空なら起動ごとに乱数)
```

## 6. セットアップ手順(実機前提。詳細は booking/pc/README.md。1 STEP ずつ)

Mac 側は準備済み: Raspberry Pi Imager、SSH 鍵 `~/.ssh/id_ed25519`(公開鍵認証のみで有効化)。

1. **OS 書き込み**(Imager): Raspberry Pi OS Lite(64-bit)を microSD に。設定: hostname `tennis-pi`、user `yu`、Wi-Fi = SoftBank Air(国 JP)、
   TZ Asia/Tokyo、keyboard jp、SSH 有効(公開鍵のみ)
2. **組み立て(ケース到着前は基板むき出しで動作確認)**: Active Cooler → M.2 HAT+(16mm ヘッダ)→ SN530 を 2230 側の穴で固定 → microSD → 電源。
   絶縁物の上に置く。`ssh yu@tennis-pi.local`
3. **初期化スクリプト**: `curl -fsSL https://raw.githubusercontent.com/y-ykym/tennis-court-monitor/main/booking/pc/pi-init.sh | bash`
   (apt full-upgrade、rpi-eeprom-update -a、Docker 公式スクリプト、usermod -aG docker、git clone、.env の雛形)。再ログイン、必要なら sudo reboot
4. **SSD の SMART 確認**(バルク品): `~/tennis-court-monitor/booking/pc/pi-check.sh --smart` → Power On Hours ≈ 0、Percentage Used 0%、Critical Warning 0x00
5. **NVMe 起動へ切替**: `rpi-clone nvme0n1 -f` で microSD の内容(設定込み)を SSD に複製 → `sudo rpi-eeprom-config --edit` で `BOOT_ORDER=0xf416` → reboot →
   `findmnt /` が nvme0n1p2 なら成功。**まず Gen2(既定)で安定確認**、Gen3 化(`dtparam=pciex1_gen=3`)は任意で後日
6. **設定と起動**: `nano ~/tennis-court-monitor/booking/pc/.env`(値は本人入力)→ `docker compose up -d --build`(初回 10〜15 分)
7. **疎通確認**: `./pi-check.sh` → `curl localhost:8080/warmup` が ok、Worker `/booking/status` が `registered: true`
8. **実枠で通し**: 署名付き URL を開いて自動予約 → 予約サイトでキャンセル(テニスは 4 日前まで無料)
9. **運用開始**: GitHub Secrets に `BOOKING_BASE_URL=https://tennis-reservation-bot.y-ykym.workers.dev` を登録 → 次の空き通知からボタンが付く
10. **仕上げ**: `sudo reboot` で自動復帰を確認、ケース到着後に P579 へ組み込み、OS 更新は手動(自動再起動はさせない)

### 更新の仕方(コードが変わったとき)
```bash
cd ~/tennis-court-monitor/booking/pc && git pull && docker compose up -d --build
```

## 8. 注意点(決着済みの項目は除いた)

- NVMe 起動は EEPROM の起動順設定(BOOT_ORDER=0xf416)が必要。microSD で起動 → rpi-clone で複製 → 切替の順が安全
- SN530 はバルク品。到着後に SMART で使用時間・書込量を確認し、異常なら店の初期不良対応(180 日)へ
- PCIe はまず Gen2 で運用。Gen3 化は任意(不安定なら戻す)
- ケース(P579)到着まで基板むき出しで運用する期間は、絶縁物の上に置き、金属や液体に触れないように
- quick tunnel の URL は起動ごとに変わる(Worker が吸収)。固定にしたければ Cloudflare にドメインが必要(現状は持っていない)
- 予約サイトのセッションは約 10 分で切れる。noVNC の画面が出たら数分以内に操作する
- 秘密情報(パスワード・署名鍵・トークン)はコードや文書に書かない。`.env` は git 管理外
